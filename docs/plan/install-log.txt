── Deviations from the plan ────────────────────────────────────────────────────

 1. MySQL is published on HOST PORT 3307, not 3306.
    A native `MySQL84` service already owns 3306 on this machine, so
    docker-compose.yml maps `3307:3306`. `MYSQL_PORT` in `.env` and `.env.example`
    must match the left-hand number. A fresh clone that assumes 3306 will fail.

 2. Docker 29.9.3 and Compose v5.7.0 are newer than the versions this plan assumed.
    No behavioural difference for this stack. Recorded because the plan named
    versions and they no longer match.

 3. DEFECT, found and fixed: a `$` in `MYSQL_PASSWORD` broke every DB connection.
    Docker Compose interpolates `$name` inside `.env` values and substitutes an empty
    string; django-environ reads the file literally. Container and app therefore held
    DIFFERENT passwords, and the failure surfaced as
    `ERROR 1045 (28000): Access denied for user 'sakayph'@'localhost'` — an error that
    points at the app rather than at the password.

    Proven before fixing:
        length in .env          50
        length Compose passes   47
        identical               False

    Fixed by regenerating the password as 32 alphanumerics, then
    `docker compose down -v` and `docker compose up -d`. The `down -v` is required:
    the MySQL entrypoint issues CREATE USER only when the data directory is empty, so
    editing `.env` alone leaves the old password in place and makes the fix look
    ineffective. Verified afterwards: `identical: True`, app user connects.

    The same defect produced a `The "xyz" variable is not set` warning on every compose
    command — easy to learn to ignore, which is why it is documented in `.env.example`
    and in the Step 1.02 troubleshooting table.

 4. Vite binds to IPv6 loopback only.
    `http://localhost:5173/` and `http://[::1]:5173/` return HTTP 200;
    `http://127.0.0.1:5173/` does not respond. Both servers were confirmed listening at
    the same moment. Open the app at `http://localhost:5173`, not the 127.0.0.1 form,
    when Phase 4 begins.

 5. Graphviz `dot` was not on PATH at this check, and the PlantUML jar was not found in
    the repository. Java 22.0.1 is present. The 13 diagrams render today, so the
    toolchain worked at some point — but confirm `dot` is reachable before the next
    re-render, since the class and component diagrams need Graphviz layout.
